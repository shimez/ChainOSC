# Chainデバイス台帳 運用ルール

この文書は、`test-data/CHAIN_DEVICE_INVENTORY.md`で管理するChainデバイスと、テスト結果への記録方法を定めます。

## 1. 台帳の目的

Chainデバイスの個体を管理IDとUIDで識別し、テストに使用した実機を後から特定できるようにします。長いUIDをテスト結果へ繰り返し転記せず、管理IDで簡潔に記録することも目的とします。

## 2. 登録対象

- UIDを持つ外付けChainデバイスを登録します。
- ChainOSCminiやChainOSCnanoなどの本体キー、ChainOSCPadの内蔵入力は登録しません。
- UIDを確認できない外付けChainデバイスは、UID欄を`未確認`として一時登録できます。確認後に更新します。

## 3. 管理ID

- デバイス種別を表す接頭辞と連番を使用します。例: `KEY-01`、`ENC-01`、`ANG-01`、`TOF-01`、`JOY-01`。
- 一度割り当てた管理IDは変更しません。
- 故障、紛失、廃棄した個体の管理IDは別の個体へ再利用しません。
- 同じデバイス種別を追加する場合は、既存番号の次の連番を割り当てます。

## 4. 台帳の更新

- 新しいChainデバイスを入手したときは、テストに使用する前に台帳へ追加します。
- UIDはシリアルログなどから確認し、転記後に桁数と内容を再確認します。
- 故障、紛失、貸出、使用停止などが発生した場合は行を削除せず、状態欄を更新します。
- 個体差、外観、識別用の印、既知の不具合などは個体メモ欄に記録します。
- UIDの訂正を含む台帳の変更はGitへコミットし、履歴を残します。

状態欄では、必要に応じて次の値を使用します。

- `使用可`
- `使用停止`
- `故障`
- `貸出中`
- `紛失`
- `廃棄`

## 5. テスト結果への記録

- テスト結果の「Chainデバイス台帳」欄には、原則として`test-data/CHAIN_DEVICE_INVENTORY.md`を記載します。
- 「使用デバイス管理ID」欄には、そのテストで実際に使用した管理IDを列挙します。
- 同じ種別の連続した管理IDは、`KEY-01〜KEY-04`のように省略できます。
- 異なる種別を使用した場合は、`KEY-01〜KEY-04、ENC-01、ANG-01、TOF-01、JOY-01`のように記載します。
- 正式な試験では「使用可の全デバイス」のような、将来の台帳更新によって意味が変わる表現は避けます。
- 本体キーなどを使用した場合は、「使用した本体入力」欄に製品名と入力名を記載します。
- 本体入力を使用しなかった場合は、`未使用`または`N/A`と記載します。

記載例:

```markdown
| Chainデバイス台帳 | `test-data/CHAIN_DEVICE_INVENTORY.md` |
| 使用デバイス管理ID | KEY-01〜KEY-04、ENC-01、ANG-01、TOF-01、JOY-01 |
| 使用した本体入力 | ChainOSCmini本体Key、ChainOSCnano本体Key、ChainOSCPad内蔵Key |
```

## 6. 個体差や異常が見つかった場合

- 特定個体だけで発生した可能性がある場合は、テスト結果の証跡または備考へ管理IDを記載します。
- 再現確認では、可能であれば同種の別個体でも試験します。
- 個体固有と判断した事項は台帳の個体メモ欄にも追記します。
- 製品実装の問題か個体の問題か判断できない場合は、結論を急がずテスト結果へ状況を残します。

## 7. 台帳と過去のテスト結果

- 台帳は現在の状態を示す共通ファイルとして更新します。
- 過去のテスト結果には、試験時点で使用した管理IDが残ります。
- 状態変更があっても過去のテスト結果は書き換えません。
- UIDや管理IDに重大な訂正があった場合は、影響するテスト結果の備考へ訂正内容を追記します。
